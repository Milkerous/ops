# 决策记录

## 背景与约束

A 组需要以真实 BuildChecker 图作为基线，在后续提交中复用未变化的图，并在 include、声明和编译配置变化时保持增量结果与全量扫描一致。实验环境为单 Make 进程、对象目标投影和固定 C 样例；个人贡献必须可测试、可复现，并避免复制其他学生实现。

## 选择与替代方案

选择：按课程 A 轨道的提交键复用历史图；普通函数体与纯声明变化继续复用实际依赖图；新 include、头文件间接 include 和 CFLAGS 变化触发保守刷新；声明图变化后单独重算 findings，避免复用旧 MD/RD。个人新增 E8、E9、E10 各一个独立测试，分别覆盖声明修复、头文件新增 include、间接 include 链。

替代方案：始终全量扫描最直接，但无法展示论文中的复用收益；只比较 findings 数量无法发现目标和依赖映射错误；只检测 `main.c` 而忽略嵌套头文件会漏掉隐含依赖；修改 `lab.py` 以获得表面性能提升会扩大贡献范围并增加回归风险，因此本次保留参考实现，仅增加验证。

## 代价与覆盖范围

小样例的刷新场景中，增量扫描和全量扫描耗时接近，不能宣称普遍加速。当前保守刷新两个对象目标可能执行不必要的预处理，但可避免漏边。测试只覆盖单一 Make 进程、成功构建和对象目标投影，不覆盖生成头文件、条件编译、并行构建或真实规模项目。

## 验证命令与实际证据

运行 E8、E9、E10 的 A 轨道入口，验证的 OUT 分别是 `work/e8-A-20261108-172652`、`work/e9-A-20261108-172700`、`work/e10-A-20261108-172708`。E8/E9 的对象图、MD/RD 与内部提交一致；E10 的 30 行全部通过 `actual/declared/findings` 集合比较，最终 BuildChecker 为 SUCCEEDED。单元测试共 10 项通过，日志为 `work/unit-tests-20261108-172909.log`。
